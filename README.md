# Система умного помещения: мониторинг и управление вентиляцией

## 1. Назначение проекта

Проект представляет собой учебный стенд умного помещения. Он собирает показания датчиков температуры `TEMP-01` и влажности `HUM-01`, передаёт их в приёмники, сохраняет историю в SQLite и управляет вентилятором `FAN-01` по температурному условию. Для мониторинга и оповещений используется связка Prometheus и Grafana.

В репозитории также сохранены материалы предыдущих практических работ по построению офисной сети в GNS3. Эти материалы относятся к сетевой инфраструктуре проекта и не являются отдельной системой мониторинга помещения.

> Документ подготовлен по содержимому переданного архива репозитория. Параметры, которые нельзя подтвердить файлами репозитория (например, текущая доступность ВМ и фактическая доставка писем), отдельно отмечены как требующие проверки на стенде.

## 3. Используемые компоненты

- **Node-RED** — периодическая генерация и передача показаний, формирование команд для вентилятора.
- **Приёмник CTRL-01** — HTTP API на порту `8080`. В репозитории имеется `Для работы 5/receiver.js`.
- **Сервис хранения DB** — HTTP API на порту `8081`, сохранение данных в SQLite. Исходный код: `Для работы 5/server.py`; Compose-файл и веб-страница истории находятся в `Для работы 6/`.
- **SQLite** — таблицы `measurements` и `actuator_events`; файл рабочей базы данных не должен публиковаться в Git.
- **Prometheus и Grafana** — сбор и отображение метрик, правила оповещений. Конфигурационные экспорты этих компонентов в переданном архиве не обнаружены, поэтому конкретные имена файлов и настройки нужно дополнить после экспорта с MON-01.

## 5. Схема обмена данными

1. Потоки Node-RED на IOT-01 формируют сообщения `TEMP-01` и `HUM-01`.
2. Показания отправляются HTTP POST-запросами:
   - на CTRL-01: `http://192.168.20.12:8080/api/readings`;
   - на DB: `http://192.168.20.10:8081/api/readings`.
3. Поток температуры проверяет условие `температура > 30 °C`:
   - выше 30 °C — формируется состояние `FAN-01 = ON`;
   - 30 °C и ниже — формируется состояние `FAN-01 = OFF`.
4. Состояние вентилятора отправляется на CTRL-01 (`/api/actuators`) и DB (`/api/actuators`).
5. Сервис DB сохраняет показания и события вентилятора в SQLite. Страница истории доступна на DB по адресу `http://192.168.20.10:8081/`.
6. Prometheus собирает метрики с настроенной цели `office-controller`, а Grafana отображает данные и обрабатывает правила оповещений. Фактические scrape-настройки и состояние `UP` должны подтверждаться на MON-01.

Условие управления `FAN-01` и периодичность inject-узлов по 5 секунд подтверждаются экспортом Node-RED `пр6/flows (1) (1).json`.

## 7. Запуск сервисов

Команды ниже соответствуют расположению Compose-файлов в репозитории. Выполняйте их на соответствующих ВМ из каталогов проекта.

### CTRL-01 — HTTP-приёмник

```bash
cd "Для работы 5"
docker compose -f compose.yml up -d
docker compose -f compose.yml ps
docker compose -f compose.yml logs --tail=50 receiver
```

Проверка доступности приёмника:

```bash
curl -i http://127.0.0.1:8080/health
```

Ожидается HTTP `200` и JSON с `"status":"ok"`. При проверке с другой ВМ используйте адрес CTRL-01 `192.168.20.12`.

### DB — SQLite и история

```bash
cd "Для работы 6"
docker compose -f compose.yml up -d
docker compose -f compose.yml ps
docker compose -f compose.yml logs --tail=50 storage
```

Проверка сервиса:

```bash
curl -i http://127.0.0.1:8081/health
curl -s http://127.0.0.1:8081/api/summary
```

Страница истории: `http://192.168.20.10:8081/`.

Проверка записей выполняется скриптом `inspect_db.py` внутри контейнера/окружения с доступом к рабочему файлу SQLite. Саму базу данных в репозиторий не добавлять.

### IOT-01 — Node-RED

Откройте `http://192.168.20.11:1880`, импортируйте актуальный экспорт `пр6/flows (1) (1).json` только если это требуется для восстановления потоков, проверьте адреса HTTP-запросов и нажмите Deploy. На рабочем стенде не импортируйте повторно потоки без предварительного экспорта действующей конфигурации.

### MON-01 — Prometheus и Grafana

Запуск служб выполняется средствами настроенной ОС и существующей конфигурации MON-01. Перед запуском проверьте фактические имена служб и их состояние:

```bash
systemctl status prometheus
systemctl status grafana-server
```

В браузере откройте `http://192.168.20.13:9090` и `http://192.168.20.13:3000`.

Конфигурации Prometheus (`prometheus.yml`, unit-файл службы) и экспорт панели/правил Grafana следует сохранить в репозитории после проверки и удаления секретов. В переданном архиве эти файлы не найдены, поэтому команды изменения конфигурации здесь намеренно не приводятся.

## 8. Проверка системы перед демонстрацией

1. Убедиться, что Node-RED доступен и оба inject-потока датчиков настроены на интервал 5 секунд.
2. Убедиться, что CTRL-01 отвечает на `/health`.
3. Убедиться, что DB отвечает на `/health`, а `/api/summary` возвращает актуальные записи.
4. Проверить поступление TEMP-01 и HUM-01 в SQLite.
5. Проверить управление FAN-01 при значениях ниже, равных и выше порога 30 °C.
6. В Prometheus проверить цель `office-controller`: статус должен быть `UP`.
7. В Grafana проверить отдельные правила отсутствия новых показаний TEMP-01 и HUM-01: возраст более 20 секунд, evaluation interval 10 секунд, Pending 0 секунд.
8. Отправить тестовое уведомление Grafana и убедиться в фактическом получении письма, включая проверку папки «Спам».
9. Поочерёдно остановить периодическую отправку TEMP-01 и HUM-01, не останавливая CTRL-01 и второй датчик; зафиксировать Alerting, письмо и возврат в Normal после восстановления отправки.
10. После испытаний восстановить штатную отправку обоих датчиков и убедиться, что система вернулась в нормальное состояние.

Результаты и подтверждения вносить в `journal.md`. Не отмечать проверку успешной без фактического результата и снимка/лога.

## 9. Безопасность и состав сдаваемых материалов

Не публиковать:
- пароли, токены, SMTP-пароли и другие секреты;
- рабочий файл SQLite и его журналы;
- каталоги данных контейнеров;
- приватные ключи и файлы учётных данных.

Публиковать можно обезличенные конфигурации, исходный код, SQL-схему и запросы проверки, экспорты потоков Node-RED и Grafana, снимки интерфейсов без секретов, инструкцию, журнал и презентацию.

Перед итоговым коммитом проверьте `git status` и содержимое добавляемых файлов.
